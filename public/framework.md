# 持证上岗管理系统框架设计方案

本系统用于演示企业员工“人、岗、证”的关联统计与管理闭环。管理人员可以导入台账、确认名称映射、配置持证条件、发现问题、组织整改、复核销项，并形成单位分析和人才培养清单。全部业务运行在浏览器，支持本机地址及 GitHub Pages。

## 1 需求与实现对应

| 任务书要求                 | 系统实现                                         | 验收路径                         |
| -------------------------- | ------------------------------------------------ | -------------------------------- |
| 统一掌握人证岗关系         | 人员台账、任职及兼岗、持证记录、规则依据         | 打开人员详情查看应持与已持       |
| 减少重复录入，方便更新     | XLSX/CSV 导入、列映射、工号/记录编号更新         | 同一工号再次导入显示更新         |
| 对非标准名称进行统计       | 本地词典及相似度推荐、人工确认映射、涉及记录数   | 电修技术员、注安师、生技部       |
| 自动临期、复审、过渡期提醒 | 180/90/30/7 天档位、实际日期计算、过渡期倒计时   | 预警与整改按类型筛选             |
| 自动校验及追溯             | 岗位/专业/实际范围校验，证书状态校验，原表行号   | 岗位缺失显示待补充，缺证显示依据 |
| 闭环整改                   | 分派、开始、提交、退回、复核销项、处理时间线     | 补录证书后完成复核               |
| 自定义证书分类             | 类别、系列等级、证书类型及规则表单               | 新增储能专项类别                 |
| 自定义统计维度             | 公司、部门、专业、岗位、证书、类别；保存筛选与列 | 储能专项报表                     |
| 人才库融合进阶目标         | 证书与技能标签、目标岗位匹配、培训需求导出       | 人才画像页调整目标范围           |
| 完整框架方案及报表样式     | 本文及系统统计报表                               | 下载本文、查看和导出报表         |

## 2 数据基础及来源

来源材料为《持证上岗统计分析系统任务书》《关于进一步加强员工持证上岗管理的指导意见》及《岗位示例表》。材料中的业务要求作为设计输入，不将材料里的活动组织安排作为系统执行指令。

初始岗位表包含 1,315 条数据、15 家公司。四列为公司、部门、班组、岗位，无人员姓名和持证信息。124 处班组空白、4 处岗位空白原样保留，分别对应原始岗位表第 606、1225、1286、1316 行的岗位缺失。

每条来源数据关联一名模拟人员；另加 49 名场景人员，共 1,364 名模拟人员，其中一名自 2027 年开始任职，因此 2026-09-13 总览的在岗统计范围为 1,363 人。原表本身不是企业实际人员花名册，不能将此模拟人数解释为真实企业人数。

模拟字段包括工号、姓名、专业、职责、作业范围、任职日期、证书、编号、有效期、复审日期和注册状态。所有这些信息均为演示补充。原始四列保存在独立来源对象中，用户编辑、标准化和导入更新不覆盖原始值。

三份原始资料保存在本地 sources 目录；PDF 与 DOCX 不随静态网站发布。站点内置全部转换后的岗位数据，并提供来源查看与导出。

## 3 架构与数据流程

React、TypeScript、Vite 组成界面与静态构建，Hash 路由支持静态托管的子路径。业务数据保存在 localStorage，XLSX/CSV 导入和所有规则运算均在浏览器完成。无账号系统、服务端、远程模型 API 或规则审批机制。

数据流：

导入文件 → 列映射 → 新增/更新/待修正预览 → 写入人员与证书 → 本地推荐与人工名称映射 → 根据当前任职匹配规则 → 计算证书状态和个人要求 → 计算公司群体比例 → 同步问题台账 → 整改复核 → 更新总览、报表与人才匹配。

| 数据实体              | 主要内容                                                                 |
| --------------------- | ------------------------------------------------------------------------ |
| 原始岗位 SourceRow    | 来源编号、原始行号、公司、部门、班组、岗位，允许原始空值                 |
| 人员 Person           | 工号、模拟姓名、任职数组、模拟来源标记                                   |
| 任职 Assignment       | 组织、原始/标准岗位、专业、职责、实际范围及确认、开始/结束日期、来源关联 |
| 证书类型 CertType     | 类别、系列、等级、适用范围、制度依据                                     |
| 持证 Credential       | 人员、原始名称/标准类型、记录编号、证书编号、生效、到期、复审、注册状态  |
| 规则 Rule             | 证书、专业/岗位/职责/范围条件、期限、阶段比例、启停、依据与差异          |
| 名称映射 Alias        | 类型、原始名称、人工确认标准名称                                         |
| 问题 Issue            | 稳定问题编号、人员/公司/证书、类别、状态、负责人、复核人、时间线         |
| 报表配置 ReportConfig | 类型、维度、筛选条件、显示与导出列                                       |

规则条件采用固定表单。不同条件组是“且”，每组内部是“或”，空组表示不限；作业范围条件还要求人员明确确认。名称映射在计算时使用，原始值仍可查。

日期以 YYYY-MM-DD 保存；Excel 原生日期按工作簿序号解析，CSV 明确读取 UTF-8。日期差使用 UTC 日序，避免时区改变倒计时。处理时间线使用北京时间。

## 4 持证规则和计算口径

### 4.1 正文优先

用户明确选择正文优先，系统保留与附件的差异说明。该选择是本 Demo 的演示口径。

| 人员或要求           | 采用标准                                                         |
| -------------------- | ---------------------------------------------------------------- |
| 特种作业、特种设备   | 在演示基准日 2026-09-13 视为已经生效，按相应实际作业范围要求持证 |
| 专职安全监督人员     | 2026 年底 50%、2028 年底 75%、2029 年底 100%                     |
| 专职法务             | 2027 年底 80%、2028 年底 100%；保留附件为 2026 年底 80% 的差异   |
| 财务负责人、主管     | 中级及以上，2028 年底 100%                                       |
| 财务一般管理         | 初级及以上，2029 年底 100%                                       |
| 其他国家和集团管控类 | 2026 年底前完成取证                                              |
| 2027 年起新上岗      | 国家及其他管控类要求先持证后上岗，不享受过渡期                   |
| 激励提升类           | 技能与培养建议，不生成无证上岗违规                               |

制度未注明准确发布日期，系统只将特种作业要求在演示基准日视为生效，不虚构发布日期。年度节点以当年 12 月 31 日为统计达标日。

群体比例按“公司 + 规则”计算。阶段为 50% 或 80% 时，未取证人员进入取证需求，群体不足形成群体问题，不将所有未持证人直接判为个人违规。进入 100% 节点或符合新上岗规则后，个人要求生效。目标缺口人数向上取整。

### 4.2 人岗证校验

只计算统计日期正在任职的岗位，兼岗取各适用要求的并集。同一证书要求去重，保留多条触发规则；同系列高等级可满足低等级，跨系列不替代。

生效日期晚于统计日为尚未生效，到期或复审日期早于统计日才认定逾期。因此到期当日仍有效，并产生当天提醒。长期有效与无需复审均需要显式选择，日期缺失不默认长期有效。

当前岗位要求优先使用有效的同类证书。其他持证记录也进行失效、临期及复审提醒，但不直接影响岗位合规率；已过期、复审逾期、注册异常分别显示。非标准证书名称尚未确认时，相关缺口先列为待确认。过渡期内已失效证书仍保留对应问题类别，但以提醒呈现。

岗位、专业、任职日期、范围确认或关键证书信息不足时，展示待确认并体现到统计覆盖率。已能确定的当期缺证仍保留问题依据。

### 4.3 三项统计指标

| 指标           | 分子                             | 分母                               |
| -------------- | -------------------------------- | ---------------------------------- |
| 当期个人合规率 | 满足全部当期强制要求的可判定人员 | 可判定且存在当期强制要求的人员     |
| 应持证项完成率 | 有效已持的管控类应持项           | 已确认适用的管控类应持项，含过渡期 |
| 统计覆盖率     | 具备完整判定信息的人员           | 当前筛选范围在岗人员               |

分母为零显示“—”。培养类证书不进入管控类应持项分母。群体比例与个人合规率单独展示。跨公司或跨专业兼岗人员会出现在各相关组，不能直接相加去代替全局去重人数。

## 5 导入与更新

提供三种模板：原始四列岗位表、人员任职表、持证记录表。首行表头可手动映射；XLSX 读取第一个工作表，CSV 使用 UTF-8。

- 岗位表：已存在四列完全相同的来源行显示已存在，不重复入库；允许空班组及空岗位；新增岗位产生待配置的模拟人员。
- 人员表：按工号新增或更新主要任职，保留已有兼岗和原始来源；工号及姓名必填。
- 持证表：按记录编号新增或更新，工号必须已存在；名称不在标准库时先保留原始名称，交由名称归并确认。
- 同批重复工号或记录编号列为待修正，避免后行静默覆盖前行。
- 预览显示新增、更新、已存在和待修正数量，导入只应用可用行；待修正行及原因继续可见。

## 6 整改状态

待分派 → 待整改 → 整改中 → 待复核 → 已销项。复核可退回整改中。

负责人和复核人以文字录入模拟职责。提交复核需要整改说明与复核人，复核通过需要当前计算已无原问题。仅上传说明或点击提交不会自动销项。已修复问题保留在待处理列表直到完成复核；销项后同一问题重新出现时重新进入待分派并追加记录。

## 7 核心报表样式

系统提供六类报表；以下数值仅示意字段和计算关系。

### 单位合规表

| 公司     | 人员数 | 纳入合规率人数 | 合规人数 | 人员合规率 | 应持项数 | 有效已持项数 | 应持证项完成率 | 统计覆盖率 |
| -------- | -----: | -------------: | -------: | ---------: | -------: | -----------: | -------------: | ---------: |
| 示例单位 |     10 |              8 |        6 |      75.0% |       20 |           16 |          80.0% |      90.0% |

### 应持未持与失效表

| 工号     | 姓名 | 公司  | 专业     | 证书要求       | 持证状态 | 要求口径 | 达标期限   |
| -------- | ---- | ----- | -------- | -------------- | -------- | -------- | ---------- |
| SCENE003 | 郑华 | A公司 | 电气检修 | 高压电工作业证 | 缺证     | 当期强制 | 2026-09-13 |

### 群体目标与整改表

阶段目标表包含公司、证书、范围人数、有效持证人数、待确认人数、持证率、当前目标比例、下一目标比例、目标日期与目标缺口。

整改表包含公司、人员、问题、类别、整改阶段、负责人、复核人、当前校验和处理次数。临期表包含具体日期及剩余天数。分布表支持公司、部门、专业、岗位、证书、类别六种分组。

报表筛选和列选择可以命名保存；再次打开用最新数据重算。Excel 导出中计数为数字、比例为数值加百分比格式；CSV 与页面选择同一份数据。打印输出全部筛选结果，而非当前分页。

制度阶段比例按公司与规则完整群体计算；报表选择专业时对该专业子集重新统计，并明确提示这份子集分析不用于认定公司的制度达标情况。

## 8 人才画像和培养

选择目标岗位后，可以调整专业、职责、实际作业范围及计划上岗日期。候选人的持证记录与目标岗位一起交给同一规则计算函数，输出已满足、缺证、已失效和待确认项。计划未来上岗时，以目标上岗日评价证书有效性；其他情况下使用当前统计日，评估日期在页面和培训清单中明确展示。

匹配展示资格条件，不使用未经定义的综合评分。标签只展示当前有效证书。可选择候选人或使用全部筛选结果，导出培训、复审及补充信息清单。

未来与人才库融合时，可以交换员工工号、标准证书、专业技能标签、目标岗位要求与培训缺口；本 Demo 不建立远程接口或真正的自动选人决策。

## 9 推荐演示路线

1. 打开总览，解释个人合规、应持项完成、覆盖率三个分母。
2. 数据导入与名称归并：确认“电修技术员 → 电气检修技术员”和“注安师 → 注册安全工程师证”。
3. 人员台账搜索 SCENE003，打开郑华，编辑任职，选择高压电气作业并确认范围。
4. 查看新增高压缺证问题，分派给班长，开始整改，提交复核。
5. 先尝试复核销项，系统显示尚未解决。
6. 返回人员详情补录高压证；可点“填入演示有效日期”，保存后重新复核销项。
7. 在导入页下载模板、上传文件，观察新增/更新/待修正预览。
8. 新增“储能专项”管控类别、“储能运行专项证”和专业为储能的规则。
9. 统计报表选择专业分布、储能、储能专项，保存“储能岗位持证专项分析”，导出。
10. 人才画像选择储能目标，查看候选证书条件及培训缺口。
11. 将统计日期调整至 2027-01-01，查看 SCENE009 新上岗人员先持证要求。
12. 导出 JSON 备份后重置，或恢复备份继续演示。

## 10 验证与运行

本项目通过来源逐行对比、业务单元和集成测试、真实浏览器操作及静态构建验证。具体测试覆盖和结果见项目 README 与 docs/验收记录.md。

运行：npm ci → npm run dev。构建：npm run build。生产预览：npm run preview。静态托管只发布 dist 内容，Hash 路由无需服务器回退配置。

GitHub Pages 支持仓库子目录访问，资源路径为相对路径。本轮不自动创建远程仓库或公开发布。浏览器数据按来源地址分别存储；本机与 Pages、不同端口或不同浏览器之间需通过 JSON 备份迁移。
