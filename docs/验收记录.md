# 验收记录

验收日期：2026-09-13。运行环境：macOS、Node.js 26、React 18、Vite 5；浏览器为 Codex 内置浏览器与 Google Chrome。本记录区分实际操作、自动检查和未完成验证，不将源代码检查等同于浏览器验证。

## 数据完整性

`npm run verify:data` 使用原 XLSX 对内置来源逐行逐字段比较。1,315 条记录、15 家公司、124 处空班组、4 处空岗位及原始行号一致。每条来源均关联一名模拟员工。补充 49 名场景人员后为 1,364 人；基准日期内在岗 1,363 人。

## 实际浏览器业务闭环

在 127.0.0.1:5178 上完成以下操作：

1. 确认“电修技术员 → 电气检修技术员”和“注安师 → 注册安全工程师证”，查看映射记录。
2. 搜索 SCENE003（郑华），编辑任职、添加高压电气作业并确认范围，观察新增高压缺证。
3. 为高压缺证分派演示班长，开始整改、填写说明并提交演示复核员。
4. 未补证即申请销项，系统拒绝并提示“问题尚未解决”。
5. 返回人员补录高压有效证书，再次复核成功销项；刷新后仍保留已销项与处理记录。
6. 导入无 BOM 的中文 CSV，预览识别一行新增、一行缺工号待修正。导入后按 BROWSER001 找到新增人员及对应缺证。
7. 通过界面新增储能专项类别、储能运行专项证和专业为储能的持证规则。报表显示 5 人、5 项要求、0 项有效已持；保存“储能岗位持证专项分析”。
8. 人才目标从储能切换为法务，满足条件人员由 0 人变为 2 人；候选人和证书条件随之变化。
9. Chrome 选择储能目标、筛选并勾选 SCENE003，导出两项培训需求（低压电工作业证缺证、电力安全技能认证证书复审逾期）；重新读取下载文件确认。
10. Chrome 导出 JSON；更改提醒天数后刷新，设置仍保留。内置浏览器导入该 JSON 并恢复成功。再修改提醒设置并重置，界面恢复 180/90/30/7，初始数据恢复。

浏览器测试产生的修改已在内置浏览器重置；Chrome 为独立测试存储。

## 报表导出证据

Chrome 实际下载的“单位合规分析.xlsx”含 15 个单位；筛选 A 公司后再次导出 Excel 和 CSV，两份文件均只有 A 公司一行。读取结果与页面一致：170 人，可判定 163 人，纳入合规率 11 人，合规 9 人；应持 386 项，有效已持 329 项。显示合规率 81.8%、应持完成率 85.2%、覆盖率 95.9%。Excel 保留数值精度并设置百分比格式；CSV 使用页面显示精度。人数保持整数，不格式化为百分比。

内置浏览器未捕获文件下载事件，实际下载验证改用 Chrome 完成。Chrome 扩展的自动文件上传受“Allow access to file URLs”设置限制，备份恢复使用内置浏览器完成；没有更改浏览器权限。

## 自动验证

`npm test` 覆盖 55 项规则、数据、导入、导出和整改回归：实际作业范围、兼岗去重、高等级替代、有效期与复审边界、群体节点、2027 新任职、正文优先、待确认、复核阻止及重开、新增规则、Excel 原生日期、UTF-8 CSV、原表完整性、报表过滤、百分比格式、非岗位必需证书的到期提醒等。

`npm run verify:ui` 核对 DESIGN.md 与生成 token 一致，并验证主要正文和状态标签配色的文字对比度至少 4.5:1。

`npm run build` 执行 TypeScript 检查与静态构建。`npm run verify:pages` 检查构建在仓库子路径下的 HTML、CSS、脚本和设计文档均可通过本机 HTTP 访问；不等同于真实浏览器子路径复验。
